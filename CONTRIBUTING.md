# Contributing

Start with the product doctrine, v1 scope, privacy architecture, and development/testing instructions in docs/. Issues with synthetic examples and clear expected behavior are welcome. Never post personal tool responses or security-sensitive material in public issues.

Licensing and contributor terms are pending. Discuss changes before submitting substantial external code; external contributions will not be merged until terms are explicit. Do not assume public visibility is a permissive license grant.

Every proposed change should explain the user problem, resulting behavior, relevant framework source, privacy/network/storage implications, accessibility behavior, and verification. Keep feature work on short branches with a PR. No AI runtime dependency, telemetry, psychological scores, or engagement mechanics. User wording stays user-owned; tools do not choose for people.

Do not modify infrastructure or production through a feature PR without its own explicit deployment review. Never commit secrets, private project sources, real answers, or server backups.
