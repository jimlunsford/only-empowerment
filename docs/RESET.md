# Reset

Phase 5 review candidate. Reset begins after behavior fell below a standard. A miss matters, but it neither erases the line nor defines the person. The outcome is a standalone **Reset Plan**, **Status: Planned**. The plan is not the reset. The next action creates the proof.

## Boundaries

Behavior is described without identity judgment. Ownership does not mean accepting blame for another person's conduct or uncontrollable circumstances. Context is useful when it reveals something repairable, without canceling responsibility. Correction addresses the miss or its effects; suffering, humiliation or deprivation are not prescribed. Structure supports the next choice without replacing ownership. Proof is future-facing observable behavior, not regret, intention or completion of the form.

No therapy, confession, root-cause tree, psychological classification, diagnostic service, excuse classification, automated rewrite, prescribed punishment, moral/severity scoring, streaks, miss history or engagement loop. Text is structurally validated, never semantically classified. The proof lesson explicitly rejects an undefined “someday” and asks the user to name today or the next real opportunity in the same authored answer. The application cannot certify that any answer is a genuine commitment or that an action occurred.

Urgent safety or professional needs take priority over completing the tool. The entry states this once; no diagnostic routing or repetitive disclaimers.

## Workflow

| Stage | Why it exists | Authorship |
| --- | --- | --- |
| What slipped | Identify correctable behavior without self-attack | What happened |
| Standard and standing | Establish the line and check whether it still applies before correction | Manual statement or explicit saved selection; still stands, review, unsure |
| Ownership | Bound responsibility to the user's actual part | What belongs to the user now |
| Weak point | Identify one useful, repairable condition without an incident investigation | What made the miss easier or keeping the line harder |
| Correction | Address what happened and its consequences without punishment | Immediate correction |
| Structure | Connect practical support to the named weak point | What to restore or change |
| Proof | End in observable action at a real opportunity | Next proof and its opportunity, in the user's own words |
| Review | Read substantially the final artifact and edit any field | Seven section-level edits |

Seven authored answers, with standard source and validity on the same stage. Back navigation preserves work. The standard/weak-point context can be opened during later steps. No-clear-standard, needs-review and unsure choices create a legitimate pause with an internal Build a Standard link. No plan is created by those branches. App-lifetime memory survives internal navigation in the same tab; reload/closure can discard it. The user can return and explicitly select an updated standard. No query-string/hash payload, generic workflow engine or server state.

## Personal Standard reference

Saved Work's existing local parser discovers only valid Personal Standards. Reset filters those entries for its deliberate picker. Nothing is automatically selected. The selector identifies area and statement, and selection reveals full Area / situation, My standard, keeping behaviors, violations, protecting structure and correction rule as read-only text in an expandable reference. The statement and validity check remain immediately available without scrolling through the full reference. The selected record is re-read and validated locally before use. Only the standard statement is copied into the plan. Other Reset answers are never prefilled from the source. The source record's bytes remain untouched.

Reference and selection identifiers live only in session memory. Source deletion or modification cannot break an existing plan: the plan owns its statement snapshot. Editing that snapshot does not alter a Personal Standard. Any statement edit, including whitespace, invalidates prior standing confirmation. Confirmation and saving require the exact statement previously marked “still stands.” The review sends the user back through this check rather than silently allowing a changed line. If the line itself needs deliberate revision, Build a Standard remains the destination.

## Artifact, copy and print

Exact fields in order:

1. What slipped (`slip`)
2. Standard I am returning to (`standard`)
3. What I own now (`ownership`)
4. Weak point to repair (`weakPoint`)
5. Immediate correction (`correction`)
6. Structure I will restore or change (`structure`)
7. Proof I will create next (`proof`)
8. Status: Planned

“Confirm Reset Plan” confirms only a plan. Planned does not mean corrected, recovered, restored, completed or proven. Confirmation remains editable; saved changes require another explicit save. The closing message encourages leaving to act. No automatic Next Move handoff or unavailable Do It Now continuation.

Each authored paragraph permits 2,000 UTF-16 code units, with visible limits before validation and no truncation. Exact wording, punctuation, Unicode and multiline text are preserved subject to native textarea newline normalization. The already accepted grapheme-safe long-token renderer is shared unchanged with Personal Standard.

Plain text begins `ONLY EMPOWERMENT` / `Reset Plan`, contains the seven labels and exact values separated by blank lines, and ends `Status` / `Planned`. No lessons, controls, metadata, storage IDs or source-record keys. Clipboard failure exposes a focused, selected, read-only manual copy area.

Print reuses the artifact stylesheet: readable flowing sections, long-word wrapping, no navigation, buttons or staging banner, monochrome meaning, small builder and secondary framework attribution. Browser Save as PDF is sufficient. Tagged accessible PDF is not claimed.

## Persistence and failure behavior

Default: memory only. Namespace: `oe:reset-plan:v1:<UUID-v4>`.

```json
{"schemaVersion":1,"id":"local UUID-v4","tool":"reset","status":"Planned","plan":{"slip":"...","standard":"...","ownership":"...","weakPoint":"...","correction":"...","structure":"...","proof":"..."}}
```

No timestamps, source IDs, whole source standard, standing/pause choices, draft history, miss counts, analytics, scores or hidden diagnoses. Exact keys, required bounded strings, schema/tool/status, UUID/key agreement and a 90,000-code-unit serialized ceiling are validated. That ceiling accommodates worst-case JSON escaping of all seven fields. No existing artifact migration or byte rewriting.

Saved Work supports Decision Record (Decided), Execution Card (Planned), Personal Standard (Set), Reset Plan (Planned). Reset summary uses miss and next proof. All types share the existing global 50 `oe:`-record limit, including unsupported records. Open, edit, copy, print, explicit save changes and delete follow accepted patterns.

Saves compare prior serialized bytes, then verify exact readback. Changed/deleted records refuse stale overwrite or silent resurrection. Full quota, storage denial and readback failures preserve memory and report uncertainty. Corrupt or unsupported records remain untouched until explicit scoped deletion. Delete My Local Data removes only `oe:` keys, verifies readback and clears all four sessions. Unrelated origin data is preserved.

BroadcastChannel, storage events and visibility rechecks extend to Reset. Deleting a saved Reset clears open saved copies and refreshes lists. Deleting a source Personal Standard does not erase an independent Reset snapshot. Existing limitations remain: browser storage is not transactional across truly simultaneous saves; without BroadcastChannel, no storage event can announce removal of a completely memory-only session when no key changed. Clipboard, print, PDF, browser/OS backups and extensions remain outside app deletion.
